# Читалка с локальным переводом: общая архитектура

## Цель
Десктопное (в браузере) приложение для чтения книг на иностранном языке с параллельным переводом локальной LLM. Исходные языки: английский, французский, испанский, итальянский, немецкий; целевой — русский. Экран делится вертикально: слева оригинал, справа перевод, выровненные по абзацам. Перевод идет в фоне с опережением позиции читателя, модель накапливает и периодически компактифицирует контекст книги (сюжет, глоссарий имен и терминов, стиль).

## Принцип: сначала движок
Конвейер перевода (импорт, контекст, перевод, валидация) это библиотека `core`. Первый клиент это CLI для пакетной конвертации и оценки качества, второй это сервер с читалкой. Существующие инструменты (bilingual_book_maker, epub-translator, CWA-eBook-Translate, pate) закрывают «показать перевод рядом», ценность этого проекта в конвейере качества, поэтому он и в центре.

## Компоненты

```
┌──────────────┐   WS (typed msgs)    ┌──────────────────┐   HTTP OpenAI-compat   ┌──────────────┐
│  Frontend    │◄────────────────────►│  Backend (Rust)  │──────────────────────►│ llama-server │
│  React/Vite  │   HTTP: upload,      │  axum + tokio    │   /v1/chat/completions│ Vulkan/ROCm  │
│  (браузер)   │   images, static     │  sqlx            │   /v1/embeddings       │ + CPU offload│
└──────────────┘                      └──────────────────┘                        └──────────────┘
                                              │   ┌────────────────────┐   ┌────────────────────┐
                                              ├──►│ PostgreSQL+pgvector│   │ llama-server (emb) │
                                              │   └────────────────────┘   └────────────────────┘
                                        ┌─────┴─────┐
                                        │  shared   │  DTO + сообщения WS, serde, ts-rs → TS-типы
                                        └───────────┘
```

- **shared** (Rust crate): типы доменной модели и протокола. Единственный источник правды для контракта; TypeScript-типы генерируются `ts-rs`.
- **core** (Rust crate): движок: импорт книг, хранилище, очередь перевода, контекст, клиент модели, экспорт. Публичный `Engine` + поток событий, без знания о транспорте.
- **cli** (Rust): импорт, пакетный перевод, экспорт двуязычного epub, eval-набор, сравнение моделей.
- **server** (Rust): тонкая обертка над `core`: WS-сервер, HTTP для загрузки и картинок, раздача статики фронта из бинарника.
- **frontend** (React + TypeScript): библиотека, двухколоночная читалка, настройки модели/промпта.
- **llama-server** (llama.cpp): отдельный процесс; чем и как он запущен — дело пользователя (юнит init-системы, скрипт, руками в соседней консоли), проект этого не предписывает. Бэкенд ходит к нему по HTTP на адрес из конфига. Бэкенд ускорителя — Vulkan или ROCm, выбирается замерами (см. `05-llm-client.md`).
- **llama-server (embeddings)**: второй экземпляр с `bge-m3` Q8_0, **на CPU** — эмбеддинги абзацев для поиска похожих мест в книге. VRAM не занимает, книга считается за ~6 с.
- **PostgreSQL + pgvector**: книги, переводы, контекст, эмбеддинги.

## Ключевые решения
| Решение | Выбор | Почему |
|---|---|---|
| Инференс | llama.cpp `llama-server` напрямую | Тонкая раскладка MoE (`--n-cpu-moe`), управление кэшем префикса, слоты, метрики. Ollama с мая 2026 сама запускает `llama-server` (PR ollama#16031), но не отдаёт наружу управление MoE-офлоадом (ollama#11772 открыт) — берём движок напрямую, Ollama остаётся fallback'ом по тому же OpenAI-совместимому API |
| Бэкенд ускорителя | **ROCm** для основной модели, Vulkan собран рядом | Решает не скорость, а вместимость: ROCm отдаёт на гигабайт больше VRAM, основная модель влезает целиком, офлоад на CPU исчезает. 65 с на книгу при разбросе ±1 с; у Vulkan офлоад остаётся, и время плавает на 20%. Если модель не влезает ни под один бэкенд, разница между ними в пределах систематики |
| Модель по умолчанию | `ggml-org/gemma-4-26B-A4B-it` (QAT, Q4_0, 128 экспертов, 8 активных), эксперты частично в RAM | QAT-веса держат качество на 4 битах; 4B активных параметров дают скорость на гибриде VRAM+DDR4; сильна на европейских языках. Второй участник сравнения — Qwen3.6-35B-A3B |
| Спекулятивное декодирование | MTP-голова через `-md … --spec-type draft-mtp` | Замерено 1.14x на целевой конфигурации, цена 382 МБ VRAM. Вывод **не** идентичен прогону без MTP: другая форма батча меняет порядок суммирования, и при близких вероятностях argmax выбирает иначе. Поэтому в `eval` MTP выключается |
| Транспорт | Один WebSocket с типизированными сообщениями и `request_id` для RPC | Двунаправленный поток: позиция читателя → бэк, переводы → фронт. REST и OpenAPI не нужны |
| HTTP остается для | загрузки книг (multipart), картинок/обложек (`GET`, кэш браузера), статики | Большие бинарные payload'ы через сокет неудобны |
| Контракт | `shared` crate + `ts-rs` | Рассинхрон DTO ловится на этапе сборки |
| UI-рендер | Браузер, epub-контент как HTML | Лучший доступный движок раскладки текста, переносы и колонки бесплатно |
| Хранилище | PostgreSQL + pgvector | Уже стоит на машине, jsonb для глоссария, векторный поиск по книге, состояние вне процесса бэка |
| Контекст для перевода | Компактная сводка + глоссарий + RAG по уже переведенным абзацам | Сводка держит сюжет, RAG подтягивает конкретные ранние места (обращения, повторяющиеся фразы) |
| Род и референции | Таблица персонажей с полом и рассказчик в промпте, препроход разметки местоимений, морфологическая постпроверка | Главная системная ошибка при переводе на русский: род глаголов и прилагательных, особенно от первого лица. Для каждого исходного языка свой набор ловушек, см. `10-gender-and-coreference.md` |
| Деплой | Один бинарник бэка со встроенной статикой (`rust-embed`); запуск — средствами пользователя | Без nginx, доступ с планшета по локальной сети. Init-система не фиксируется: на машине разработки OpenRC, а не systemd |
| Единица перевода | Абзац со стабильным id | Выравнивание колонок по абзацам, а не по страницам |

## Два режима перевода
1. **Живой префетч**: окно N абзацев впереди позиции читателя, приоритет ближайшим.
2. **Полный перевод книги** (ночной): вся книга по порядку, можно более тяжелой моделью. Читатель открывает уже готовое.

Оба режима используют одну и ту же очередь и один и тот же механизм контекста.

## Потоки данных
1. Пользователь загружает epub/fb2 → бэк парсит в главы и абзацы со стабильными id → Postgres; фоновая задача считает эмбеддинги абзацев.
2. Фронт открывает книгу по WS, получает главу (абзацы + уже готовые переводы), сообщает позицию.
3. Планировщик формирует окно префетча, воркер для каждого абзаца находит 2-3 похожих уже переведенных абзаца (pgvector), переводит, пишет в Postgres, шлет `ParagraphTranslated`.
4. Каждые K абзацев воркер ставит задачу компактификации: модель обновляет сводку сюжета и глоссарий. Новая версия контекста используется для следующих абзацев.

## Структура репозитория
```
/crates/shared      DTO, протокол, ts-rs экспорт
/crates/core        движок (см. 11)
/crates/cli         reader-cli
/crates/server      axum + WS
/crates/migrate     reader-migrate: единственное место, где накатываются миграции

```
