# 10. Род, местоимения, обращение

## Проблема
Русский маркирует род в каждом глаголе прошедшего времени и в прилагательных. Когда исходный язык эту информацию не несёт или несёт в другом виде, модель при неоднозначности выбирает статистический дефолт (обычно мужской) и меняет решение от абзаца к абзацу. Особенно страдают: повествование от первого лица, диалоги без атрибуции реплик, персонажи, введённые только местоимением.

Форма проблемы зависит от исходного языка:

| Язык | Что с родом | Что добавляется |
|---|---|---|
| **EN** | Род не маркируется нигде, кроме `he/she`. Худший случай: от первого лица нет вообще никаких сигналов | — |
| **FR / ES / IT** | Род маркируется на прилагательных и причастиях (`je suis allée`, `estoy cansada`), пол персонажа обычно выводится из текста → **задача проще, чем с EN** | **T/V**: tu/vous, tú/usted, tu/Lei |
| **DE** | Грамматический род систематически **противоречит** природному: `das Mädchen` — средний род о девочке, `die Person` — женский о ком угодно. Модель рискует перенести грамматический род в русский | **T/V**: du/Sie |

Отсюда два следствия. Первое: набор ловушек и метрики строятся **по языку**, а не общим списком. Второе: для FR/ES/IT/DE выбор «ты/вы» не надо угадывать — он **извлекается из оригинала**, и это точный сигнал, которого при EN→RU не было вовсе.

## Задачи

### Модель персонажей в контексте
- [ ] Расширить `ContextSnapshot`: поле `narrator` и таблица `characters` (схема ниже), обновляются при компактификации.
- [ ] `scene_state`: кто сейчас в сцене, кто говорил последним; пишется при компактификации и в конце каждой главы.
- [ ] Определение рассказчика при импорте: отдельный запрос по первым 2-3 главам «кто рассказчик, лицо, пол, свидетельства из текста, уверенность». При уверенности ниже порога или отсутствии свидетельств показать вопрос в UI при первом открытии книги; ответ пользователя фиксируется как `narrator.gender_source = user`.
- [ ] UI: редактирование таблицы персонажей (пол, перевод имени, ты/вы), изменение поднимает `context_version` и инвалидирует переводы начиная с текущей позиции (по желанию пользователя: только вперёд или перевести заново с начала).

### Извлечение обращения (FR/ES/IT/DE)
- [ ] При аннотации абзаца (см. ниже) фиксировать форму обращения между персонажами из оригинала: `tu/vous`, `tú/usted`, `tu/Lei`, `du/Sie` → `characters[].address`.
- [ ] Значение, извлечённое из текста, помечается `address_source = text` и имеет приоритет над догадкой модели; для EN остаётся `address_source = inferred`.
- [ ] Смена обращения по ходу книги (переход на «ты») — событие сюжета, фиксируется при компактификации, а не затирается молча.

### Препроход разрешения референций
- [ ] Задача `Annotate { paragraph_id }` в очереди, приоритет выше `Translate` того же абзаца; выполняется той же моделью, короткий вывод.
- [ ] Промпт: «размести после каждого местоимения и реплики, к кому она относится: `she [Anna]`, `I [narrator, f]`, `"..." [said: Tom]`. Используй таблицу персонажей и состояние сцены. Если не уверен, пометь `[?]`». Вход: предыдущие 2 абзаца + текущий.
- [ ] Для DE дополнительно: помечать случаи расхождения грамматического и природного рода (`das Mädchen [Anna, f]`), чтобы переводчик не унаследовал средний род.
- [ ] Результат хранится в `paragraph_annotations(paragraph_id, context_version, annotated_text, uncertain bool)`; переводчик получает размеченный текст вместо сырого.
- [ ] Неуверенные пометки `[?]` попадают в `ContextCompacted`/UI как места, где стоит проверить перевод.

### Постпроверка морфологии
- [ ] Модуль `validate/gender.rs`. Русская морфология: `pymorphy3` через отдельный небольшой сервис или Rust-аналог (проверить наличие; фолбэк: словарь окончаний для глаголов прошедшего времени и кратких прилагательных). Проверка идёт по **русскому выходу** и потому одинакова для всех исходных языков.
- [ ] Правила:
  - глагол прошедшего времени или краткое прилагательное при подлежащем «я» → род должен совпадать с `narrator.gender`;
  - то же при подлежащем-имени из таблицы персонажей;
  - при местоимении «он/она» как подлежащем сверять с ближайшим референтом из аннотации.
- [ ] Несовпадение → один ретрай с явным указанием: «Рассказчик женщина. Исправь: «пошел» → «пошла»». Повторное несовпадение → `TranslationFailed` с причиной `gender_mismatch`, в UI подсвечивается.
- [ ] Проверка согласованности «ты/вы»: если в пределах диалога форма прыгает, а `address_source = text` — ретрай с указанием формы.
- [ ] Метрика: доля абзацев с ретраем по роду, отдельно для первого лица и отдельно по каждому исходному языку.

### RAG как поддержка
- [ ] В хвост промпта из похожих абзацев брать в первую очередь те, где встречаются те же персонажи (фильтр по аннотациям), а не только по косинусной близости.

## Схема контекста
```json
{
  "lang_src": "de",
  "narrator": { "person": 1, "gender": "f", "name": "Ellen", "confidence": 0.9, "gender_source": "text|user" },
  "characters": [
    { "name": "Ellen", "ru": "Эллен", "gender": "f", "role": "рассказчица", "aliases": ["El"] },
    { "name": "Tom",   "ru": "Том",   "gender": "m", "role": "брат Эллен",
      "address": { "Ellen": "ты" }, "address_source": "text" }
  ],
  "scene_state": { "present": ["Ellen", "Tom"], "last_speaker": "Tom", "location": "кухня" },
  "terms": { "the Shire": "Шир" },
  "style": { "tense": "прошедшее", "register": "нейтральный" },
  "summary": "..."
}
```

## Порядок внедрения
1. Таблица персонажей и `narrator` в голове промпта (дешево, дает большую часть эффекта).
2. Постпроверка для первого лица.
3. Извлечение обращения для FR/ES/IT/DE — дешевле аннотаций и даёт точный сигнал.
4. Препроход аннотаций.
5. Состояние сцены и фильтр RAG по персонажам.

## Тестовый набор
По 30-50 абзацев **на каждый исходный язык**, с известными ловушками и ожидаемым родом:

- общие: рассказчица от первого лица, диалог двух женщин, персонаж, введённый по местоимению;
- EN: «they» единственного числа, отсутствие любых сигналов рода от первого лица;
- FR/ES/IT: согласование причастий (`je suis allée`), переход tu↔vous по ходу сцены;
- DE: `das Mädchen` и другие расхождения грамматического и природного рода, du↔Sie.

Гонять на каждой смене промпта или модели. Метрики: доля правильных родов при первом ответе и после ретрая; доля правильного «ты/вы» там, где форма извлекается из оригинала.
