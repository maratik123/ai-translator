# 04. Конвейер перевода: планировщик, воркер, контекст

## Задачи
- [ ] `scheduler`: окно префетча `[pos, pos + N]` (N из настроек, по умолчанию 40 абзацев ≈ 5-8 страниц), задачи в heap по приоритету `distance_from_reader`.
- [ ] Триггеры пересчета окна: `SetPosition`, `LoadChapter`, завершение задачи, смена настроек модели/промпта.
- [ ] Режим `TranslateBook`: фоновая задача с низким приоритетом, идет по порядку от начала, пропускает уже переведенное.
- [ ] `worker`: цикл `next_task → check cache → annotate (см. 10) → retrieve similar → build prompt → llm → validate → store → emit`.
- [ ] `retrieve`: эмбеддинг текущего абзаца (или готовый из БД), запрос из `03-storage.md`, **top-3 без жёсткого порога** плюс мягкая отсечка мусора по cosine distance < 0.5 (для bge-m3, см. ниже). Если эмбеддинга еще нет, пропускаем без ожидания.

  Порог откалиброван на живой книге (92 абзаца, **bge-m3**, 4186 пар). Распределение косинусной близости между парами абзацев **одной книги**: медиана 0.496, 75-й процентиль 0.557, 95-й 0.655, 99-й 0.717, максимум 0.842. Порог, который стоял в первой редакции этой доки (близость > 0.60), отсекал бы верных соседей — **он отменён**. Берём top-k, а расстояние используем только как защиту от случая «похожего нет вообще»: для bge-m3 это расстояние < 0.5, то есть примерно медиана распределения.

  **Порог привязан к модели.** У другой эмбеддинг-модели распределение другое: та же книга на `Qwen3-Embedding-0.6B` давала медиану 0.356 вместо 0.496. При смене модели порог надо пересчитать, а не переносить.
- [ ] Компактификация: каждые K абзацев (по умолчанию 60) или при смене главы ставится `CompactContext`. Промпт: старая сводка + глоссарий + оригинал и перевод абзацев с прошлой компактификации → новая сводка (≤ 300 слов) и обновленный глоссарий (JSON через `response_format`/grammar).
- [ ] Версионирование контекста: перевод абзаца использует последнюю версию с `upto_paragraph < paragraph`. Перевод в режиме префетча не ждет компактификации, идет с текущей версией.
- [ ] `validate`: пустой ответ, ответ = оригинал, число предложений отличается более чем на 50%, наличие служебных фраз («Here is the translation») и рассуждения перед ответом, проверка рода и согласованности «ты/вы» (см. `10-gender-and-coreference.md`). Ретрай один раз с указанием причины.
- [ ] `validate`: пустой `content` при непустом `reasoning_content` → причина `reasoning_overflow`, ретрай с `enable_thinking: false`. Отдельный случай, потому что обычная проверка «пустой ответ» не объясняет причину.
- [ ] `validate`: варианты перевода в скобках («Я был уставшим. (или: Я устал.)») — модель выполняет инструкцию «только перевод» не всегда; ловить по маркерам «(или», «/», «вариант».
- [ ] `validate`: **слова, которых нет в словаре**. На книге целиком это дало больше пользы, чем проверка согласования: нашлись опечатка, два выдуманных слова и искажённая до бессмыслицы фраза. Ни одна другая проверка их не видит: предложения не пустые, длина в норме, число предложений сходится.
  Нужен фильтр ложных срабатываний: разговорный, сниженный и заимствованный слой в словарях отсутствует, и без фильтра он даёт около 80% ложных срабатываний. Вариант — белый список на книгу плюс порог по частотности, а не голый словарь.
- [ ] `validate`: **проверка соблюдения глоссария**. Если в оригинале абзаца встречается термин, закреплённый в `terms` (см. `10-gender-and-coreference.md`), в переводе обязан быть его закреплённый эквивалент. Дёшево, детерминированно и покрывает класс ошибок, слепой для всего остального (см. ниже).
- [ ] `validate`: прокси на **тихое смягчение** — обвал отношения длин оригинал/перевод плюс детектор отказных формул на русском и на языке оригинала. Обычные проверки его не ловят: ответ не пустой, не эхо, число предложений сходится.
- [ ] Метрики: ток/с, время на абзац, глубина опережения, попадания в кэш.

**Замер на 92 абзацах** (голова ~150 токенов, хвост — 2 предыдущие пары «оригинал → перевод»): 1.7 с на абзац, попадание в кэш префикса **30%**, промпт 35.4k токенов на книгу при 5.1k сгенерированных. Доля кэша тут равна отношению «голова / (голова + хвост)», поэтому она тем выше, чем больше стабильная часть. В продакшене голова содержит сводку и глоссарий и будет в разы длиннее этого теста — то есть 30% это нижняя оценка. Прямое следствие: всё, что стабильно (глоссарий, таблица персонажей, правила регистра), должно жить в голове, а не подмешиваться в хвост.

## Промпт перевода (набросок)
```
system: Ты литературный переводчик с {src} на {dst}. Переводи только данный абзац,
без пояснений, сохраняй inline-разметку <em>/<strong>. Следуй глоссарию.
Рассказчик: {narrator} (лицо, пол). Персонажи (имя, пол, перевод имени, обращения): {characters}
Контекст книги (версия {v}): {summary}
Сцена: {scene_state}. Термины: {terms}

user: Похожие ранние места книги (оригинал → перевод): ...
Предыдущие абзацы (оригинал → перевод): ...
Переведи: {paragraph.html}
```
- Голова промпта (system) стабильна между абзацами → кэш префикса.
- `max_tokens` = 3 × длина абзаца в токенах.
- Параметры сэмплинга задаются в каждом запросе и описаны в `05-llm-client.md`. Ключевое: температура 0.2-0.3 ради воспроизводимости и **`repeat_penalty` явно 1.0** — штраф за повтор работает против требования следовать глоссарию, потому что имена персонажей и термины обязаны повторяться.

## Глоссарий и персонажи
Полная схема контекста (рассказчик, таблица персонажей с полом, состояние сцены, термины, стиль) описана в `10-gender-and-coreference.md`.

## Класс ошибок, который не ловит ничего
Замерено на живой книге. В одном абзаце английский глагол, у которого есть омонимичное существительное совсем из другой области, был прочитан как это существительное. Модель затем пристроила к нему соседнее слово, и получилось словосочетание, которого в оригинале нет вовсе.

Из 12 прогонов разных моделей и настроек 5 перевели абзац верно, 7 — с этой подменой, причём в нескольких разных формулировках. Слово-омоним встречается в книге один раз, и ровно там единственный сбой: там, где в оригинале стоит то самое существительное в прямом значении, все 12 переводов верны.

Ошибка проходит **все** проверки: ответ не пустой, не эхо, число предложений сходится, отказных формул нет, слов вне словаря нет (все словарные), согласование безупречно, отношение длин в норме. Беглая, грамматичная и правдоподобная бессмыслица.

Результат вдобавок нестабилен: на одной и той же модели он колеблется от прогона к прогону из-за недетерминированности, описанной в `05-llm-client.md`.

**Косинусная близость к оригиналу как детектор не работает — проверено.** Идея была использовать уже считаемые для RAG эмбеддинги: сравнить абзац с его переводом и отбраковать просевшие. Замер (bge-m3): верные варианты 0.847, испорченные 0.799-0.823, а медиана по книге 0.835 при 5-м процентиле 0.718. Испорченный вариант остаётся в верхней половине распределения, глобальный порог его не увидит: просадка 0.048 меньше естественного разброса между абзацами.

При этом **ранжирование вариантов одного абзаца** работает: из 12 переводов верные заняли первые места. Отсюда гипотеза «best-of-N с переранжированием по близости к оригиналу» — но это один пример и N-кратная стоимость, так что проверять отдельно.
