# 04. Конвейер перевода: планировщик, воркер, контекст

## Задачи
- [ ] `scheduler`: окно префетча `[pos, pos + N]` (N из настроек, по умолчанию 40 абзацев ≈ 5-8 страниц), задачи в heap по приоритету `distance_from_reader`.
- [ ] Триггеры пересчета окна: `SetPosition`, `LoadChapter`, завершение задачи, смена настроек модели/промпта.
- [ ] Режим `TranslateBook`: фоновая задача с низким приоритетом, идет по порядку от начала, пропускает уже переведенное.
- [ ] `worker`: цикл `next_task → check cache → annotate (см. 10) → retrieve similar → build prompt → llm → validate → store → emit`.
- [ ] `retrieve`: эмбеддинг текущего абзаца (или готовый из БД), запрос из `03-storage.md`, фильтр по cosine distance < 0.4, максимум 3 пары. Если эмбеддинга еще нет, пропускаем без ожидания.
- [ ] Компактификация: каждые K абзацев (по умолчанию 60) или при смене главы ставится `CompactContext`. Промпт: старая сводка + глоссарий + оригинал и перевод абзацев с прошлой компактификации → новая сводка (≤ 300 слов) и обновленный глоссарий (JSON через `response_format`/grammar).
- [ ] Версионирование контекста: перевод абзаца использует последнюю версию с `upto_paragraph < paragraph`. Перевод в режиме префетча не ждет компактификации, идет с текущей версией.
- [ ] `validate`: пустой ответ, ответ = оригинал, число предложений отличается более чем на 50%, наличие служебных фраз («Here is the translation») и рассуждения перед ответом, проверка рода и согласованности «ты/вы» (см. `10-gender-and-coreference.md`). Ретрай один раз с указанием причины.
- [ ] `validate`: пустой `content` при непустом `reasoning_content` → причина `reasoning_overflow`, ретрай с `enable_thinking: false`. Отдельный случай, потому что обычная проверка «пустой ответ» не объясняет причину.
- [ ] `validate`: варианты перевода в скобках («Я был уставшим. (или: Я устал.)») — модель выполняет инструкцию «только перевод» не всегда; ловить по маркерам «(или», «/», «вариант».
- [ ] `validate`: **слова, которых нет в словаре**. На книге целиком это дало больше пользы, чем проверка согласования: нашлись опечатка («Момент повис в возду**ге**»), выдуманный глагол («успела **раздуметь**»), выдуманное существительное («свидетелем нашей **распутины**») и искажённая фраза («я сосцы сосчу еще с тех пор, как…»). Ни одна другая проверка их не видит: предложения не пустые, длина в норме, число предложений сходится.
  Нужен фильтр ложных срабатываний: разговорная и обсценная лексика в словарях отсутствует («похрен», «пофиг», «кайфово», «охеренный», «оттрахал», «хайроллеры», «спорткар»). Вариант — белый список на книгу плюс порог по частотности, а не голый словарь.
- [ ] `validate`: прокси на **тихое смягчение** — обвал отношения длин оригинал/перевод плюс детектор отказных формул на русском и на языке оригинала. Обычные проверки его не ловят: ответ не пустой, не эхо, число предложений сходится.
- [ ] Метрики: ток/с, время на абзац, глубина опережения, попадания в кэш.

**Замер на 92 абзацах** (голова ~150 токенов, хвост — 2 предыдущие пары «оригинал → перевод»): 1.7 с на абзац, попадание в кэш префикса **30%**, промпт 35.4k токенов на книгу при 5.1k сгенерированных. Доля кэша тут равна отношению «голова / (голова + хвост)», поэтому она тем выше, чем больше стабильная часть. В продакшене голова содержит сводку и глоссарий и будет в разы длиннее этого теста — то есть 30% это нижняя оценка. Прямое следствие: всё, что стабильно (глоссарий, таблица персонажей, правила регистра), должно жить в голове, а не подмешиваться в хвост.

## Промпт перевода (набросок)
```
system: Ты литературный переводчик с {src} на {dst}. Переводи только данный абзац,
без пояснений, сохраняй inline-разметку <em>/<strong>. Следуй глоссарию.
Рассказчик: {narrator} (лицо, пол). Персонажи (имя, пол, перевод имени, обращения): {characters}
Контекст книги (версия {v}): {summary}
Сцена: {scene_state}. Термины: {terms}

user: Похожие ранние места книги (оригинал → перевод): ...
Предыдущие абзацы (оригинал → перевод): ...
Переведи: {paragraph.html}
```
- Голова промпта (system) стабильна между абзацами → кэш префикса.
- `max_tokens` = 3 × длина абзаца в токенах.
- Параметры сэмплинга задаются в каждом запросе и описаны в `05-llm-client.md`. Ключевое: температура 0.2-0.3 ради воспроизводимости и **`repeat_penalty` явно 1.0** — штраф за повтор работает против требования следовать глоссарию, потому что имена персонажей и термины обязаны повторяться.
