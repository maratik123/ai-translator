# ai-translator

Читалка книг на иностранном языке с параллельным переводом локальной LLM: слева оригинал,
справа перевод, выровненные по абзацам. Перевод идёт в фоне с опережением позиции читателя,
модель накапливает и периодически компактифицирует контекст книги — сюжет, глоссарий имён
и терминов, стиль.

## Статус

**Кода ещё нет.** В репозитории лежит проектная документация и один инструмент замера.
Документация на русском.

Написанное в `docs/` — это либо решения, подкреплённые замерами на конкретной машине
(числа и условия приведены), либо явно помеченные гипотезы, которые ещё предстоит проверить.
Отвергнутые варианты оставлены вместе с причиной отказа: это сокращает время следующему,
кто пойдёт той же дорогой.

## Чем этот проект отличается

Показать перевод рядом с оригиналом умеют `bilingual_book_maker`, `epub-translator`
и ещё несколько инструментов. Ценность здесь не в этом, а в конвейере качества перевода:

- **контекст книги**: компактная сводка сюжета и глоссарий, плюс поиск похожих уже
  переведённых мест по эмбеддингам — чтобы имя персонажа и повторяющийся оборот
  переводились одинаково на протяжении всей книги;
- **род и кореференция**: главная системная ошибка при переводе на русский — род глаголов
  и прилагательных, особенно от первого лица. Таблица персонажей с полом, разметка
  местоимений препроходом, морфологическая постпроверка (`docs/10`);
- **валидация перевода**: пустой ответ, эхо оригинала, преамбулы вида «Here is the
  translation», рассуждения вместо перевода, нарушения глоссария, слова вне словаря,
  тихое смягчение текста. Отдельно разобран класс ошибок, который не ловит ни одна
  из проверок, — беглая грамматичная бессмыслица (`docs/04`);
- **воспроизводимость замеров**: у локального сервера есть недетерминированность,
  у спекулятивного декодирования своя, у офлоада на CPU своя. Условия, при которых
  сравнение моделей вообще что-то значит, выписаны явно (`docs/11`).

Планируемая архитектура: движок на Rust (`core`) как библиотека, поверх него CLI и тонкий
сервер на axum с WebSocket, читалка на React, хранилище PostgreSQL + pgvector, инференс —
`llama-server` из llama.cpp по OpenAI-совместимому API.

## Документация

Начинать с [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — общая картина и таблица ключевых
решений. Дальше файлы `01`–`11` по подсистемам; самый плотный по замерам — `05-llm-client.md`
(выбор модели и бэкенда ускорителя, раскладка MoE, спекулятивное декодирование, эмбеддинги).
