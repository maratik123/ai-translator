# Tool / Subagent / Skill / Hook inventory

The live registry of the harness surface in this repository. **`AGENTS.md` § *Propagation Rule* requires updating this page in the same PR as any change to a Tool, Subagent, Skill or Hook contract.** A row that no longer matches reality is a defect, not documentation debt.

The harness was transplanted from the lab-game project in one commit, adapted to Rust and to this project's domain. This page lists what exists **now**, not what is planned.

| `PostToolUse` | `Bash` | in-flight marker stamp | When the main agent's command creates `ai-docs/plans/.task-inflight` or appends a `claim:` line to it, appends `owner: <session id>` from the hook's own input. A subagent's command never stamps. Never blocks. |

| `Stop` | — | `/task` in-flight gate | **Blocks (exit 2)** ending a turn of the marker's owning session while the marker exists and no hand-back token is in its tail; appends `blocked:` to the marker's ledger; spends a token it permits. Verification protocol for any hook change: [`hook-verification.md`](hook-verification.md). Re-derive the count rather than trusting a sentence: `jq -r '.hooks[][].hooks[].command' .claude/settings.json` — at the transplant it yielded `SessionStart` 2 · `PreToolUse` 12 · `PostToolUse` 5 · `Stop` 1, and every body passed `shellcheck -s bash`, which CI's Harness-guards job re-runs on every change.

**What the transplant verified, and what it could not.** Every guard suite listed below was run green against the adapted bodies, and the three new gates (comment references, the panic gate, the dependency direction) were driven red on purpose first, on fixtures whose payloads are real Rust, shell and YAML. MUST 3 of the verification protocol — proving a hook fires **in a live session of this repository** — could not be discharged from outside it: the harness was assembled in a work clone, not run. The first session in this checkout discharges it.

## Subagents — `.claude/agents/`

| Agent | Model | Spawned by | Contract |
|---|---|---|---|
| `spec-writer` | inherit | `/interview`, `/task` Steps 1–5 | Drafts the spec one interview round at a time; asks 0–3 questions per round or returns `ready` / `unresolvable`. Never implements. Reads every linked issue and pull request itself, and has `WebFetch` / `WebSearch`. Writes only what the task needs to count as solved: every Scope item, Key decision and AC ends with an anchor quoting the owner's words (`check-spec-anchors.sh`), and how the solution is built is the design's. |
| `design-writer` | inherit | `/task` Step 6 | Produces the design document with decomposition and a `## Handoff plan`. Reads the binding-constraint file for anything it specifies, every linked issue, and the web where the design depends on a page. Writes no code. |
| `design-review` | inherit | `/task` Step 7 | Reviews a design against the task, the spec and the checklist; issues GO / ITERATE / STOP; raises `SPEC-REMIT` against a spec row outside the spec's zone. |
| `code-writer` | sonnet, effort medium (pinned in frontmatter) | `/context-reset` group handoff | Implements a group's subtasks sequentially, gates and commits per subtask. **Never** pushes, opens a PR, runs self-review, or spawns anything. |
| `self-review` | inherit | `/task` Step 10, `/bugfix` Step 6, `/project-review` | Reviews the implementation diff against the task, the spec and the design; APPROVE / REJECT. The push gate. |
| `review-findings` | inherit | `/project-review` | Walks the whole codebase (no diff, no spec) and writes a findings table into the progress file. |
| `self-improve` | inherit | `/improve` | Reads `learnings.md` for repeating patterns, proposes instruction diffs, escalates to hooks at ≥3 occurrences. Re-verifies every factual claim it carries out of an entry. Writes no code. |
| `self-reflect` | inherit | `/reflect` | End-of-work retrospective: a structured good/bad list, each finding routed {learnings \| ticket \| none}. Assembles and yields; the parent performs every write. |
| `learnings-escalation-audit` | opus | `/ai-audit` Phase 1 | Verifies every entry's `Escalated?` and `Superseded by:` still point at something real; fixes drift **only** in those two fields. |
| `triage-runner` | opus | `/triage` | Promotes untracked `_inbox.jsonl` rows to issues, drains the queue, reconciles JSONL ↔ issue divergence. Mutation scope is `ai-docs/deferred/**` plus `gh issue` only. |

Model column: `inherit` = the orchestrator's model, via `model: inherit` in the agent's frontmatter; a named alias is a frontmatter pin. No spawn passes an inline `model=` — the frontmatter is the only lever.

## Skills — `.claude/skills/`

| Skill | Invocation | Contract |
|---|---|---|
| `/task` | explicit | The full workflow: interview → spec → design → design-review → implementation → verify → self-review → PR. Steps are strictly ordered; 6 / 7 / 10 cannot be skipped. Pre-authorises its own commits, push and `gh pr create`. |
| `/interview` | explicit or via `/task` | Drives the spec-drafting rounds through `spec-writer`; never drafts the spec itself. Runs the three spec gates itself before the owner approves — its whole check of the spec's zone is their exit codes. |
| `/context-reset` | at every design-defined group boundary, and on compaction recovery | The handoff protocol: spawns the group's implementor and re-validates state on return. |
| `/project-review` | explicit | Whole-codebase review on the current branch: `review-findings` → fix loop → `self-review` until APPROVE, then commits. |
| `/bugfix` | model-invocable on failure signals | Trace → root cause → failing test → fix. Analysis before code; the test is written before the fix. |
| `/next` | explicit | Recommends one task to work on next, with runners-up. |
| `/verify-change` | explicit | Runs `cargo test --workspace`, optionally filtered. |
| `/improve` | explicit | Launches `self-improve`; the escalation path from the corrections log into instruction files and hooks. Run at ≥3 unescalated corrections or ≥2 validations. |
| `/reflect` | explicit | Launches `self-reflect`, then applies each finding per the user's per-finding routing consent. |
| `/ai-audit` | explicit | Two phases: (1) `learnings-escalation-audit` fixes field drift; (2) the main session audits the whole instruction surface for dead references, format violations and size-cap breaches. Owns the citation guard and its regression suite. |
| `/triage` | explicit | Launches `triage-runner`; batched promotion of deferred rows to issues. Default threshold ≥3 unhandled rows. |
| `/pr-commented` | explicit | One round of reviewer-comment response: classify each unresolved thread, bundle fixes into one commit, self-review, push, reply and resolve per category. |
| `/pr-ci-failed` | model-invocable | One round of CI-failure response on the current PR: classify, reproduce locally, fix, self-review, push, re-read the PR body. |
| `/master-ci-failed` | model-invocable | Same, for a red run on `master` — the fix lands on a NEW branch and a new pull request; `master` is never modified directly. |
| `/pr-merged` | explicit | After a merge: switch to `master`, pull, delete the fallback progress files, delete the local branch. |
| `/dependabot-pr` | explicit | One round of triage on a Dependabot **cargo** pull request. Never auto-merges, never pushes to the bot branch; prints the merge command and pauses. |

Built-in Claude Code commands (`/code-review`, `/simplify`, `/security-review`, `/init`) are **not** part of this harness and are not governed by this page. They overlap `self-review` / `project-review` in purpose but not in contract: the harness surfaces review against *this* project's spec, design and domain invariants, and gate the push; the built-ins review a diff on general principles and gate nothing.

Not transplanted, because this project does not have their subject: the golden-image checker (this project's goldens are text) and the source project's own design-corpus skills.

## Permissions

`allow` covers the project's own toolchain (`cargo`, `rustc`, `rustfmt`, `rustup`, `make`, `git`, `gh`, `ast-index`, `psql`, `podman`, `python3`, `actionlint`, `shellcheck`) plus read-only text tools, and `WebFetch` / `WebSearch` unrestricted, so a background delegate (`spec-writer`, `design-writer`) never hits a permission prompt it cannot answer: those delegates read the documentation of the crates, of Postgres, of pgvector and of the model server, and a domain list would only ever be stale. `deny` covers `.idea/**`, `**/secrets*`, `**/.secrets*` and the environment files that carry a real secret — `**/.env` plus one entry per named variant. The database connection string must be unreachable to both `Read` and `Edit`, and `Edit(...)` also governs `Write`. The rules enumerate the real files rather than using a broad catch-all because the matcher takes gitignore syntax with no in-pattern negation, and `deny` is final — no `allow` entry can carve an exception out of it. A new environment file whose name is not on that list is therefore **not** denied until it is added.

## CI — `.github/workflows/ci.yml`

| Job | Runs when | Gates |
|---|---|---|
| Detect changes | always | The paths filter every other job reads |
| Format | Rust paths changed | `make fmt-check` — `cargo fmt --all --check` prints no diff |
| Build | Rust paths changed | `make build`, `make doc-check` (rustdoc with warnings denied), `make lock-check` (the manifest and the lockfile agree), `make import-guard` |
| Lint | Rust paths changed | `make clippy` with warnings denied, `make file-limits` (the hard line bands), `make panic-calls` |
| Test | Rust paths changed | `make test` — the whole workspace, each database-backed test provisioning its own container |
| Coverage ratchet | Rust paths changed | `make cover-ratchet` — the ratchet script in `--check` mode, which measures and compares but never records a new mark |
| Harness guards | `.claude/**`, `ai-docs/**`, `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `.githooks/**`, `Makefile`, `.github/workflows/**` changed | `make shellcheck` — the same command a local run uses — plus shellcheck on every hook body; the citation guard; the `context-status.md` locator check; the script-shape checker; the harness-gaps provenance and target checks; the check that the workflow's jobs and the ruleset's required checks are one set; the three spec gates; every guard regression suite; every relative markdown link resolves. **No size check**: instruction-file bytes are `/ai-audit`'s exclusive property, and CI deliberately carries no gate over them |
| Comment references | any path of the gated set changed | `make comment-refs` — no comment in a gated file points outward |
| Actionlint | `.github/workflows/**` changed | `actionlint` via reviewdog |

**A filtered-out job is not a passing job.** The paths filter decides what runs; a new artefact class must be added to it in the same pull request that introduces it, or its gate silently stops running.

**While the workspace is empty, every Rust gate skips itself loudly and exits 0** — there is no manifest at the root until the first crate lands. The skips disappear with the commit that creates the workspace; no gate has to be switched on by hand.

**Which of these checks block the merge button is the `master` ruleset's to say**, not this page's. A required check is matched by the job's display name; renaming or removing a job without the same change to the ruleset leaves that check pending for ever and blocks every pull request. `ai-docs/scripts/check-ruleset-checks.sh` refuses a tree whose job names and required checks differ in either direction, and passes with a notice when no rule requires checks. The ruleset itself is the owner's to change.

## Dependabot — `.github/dependabot.yml`

Weekly. One ecosystem today — `github-actions` (commit prefix `ci`), five open pull requests. The `cargo` ecosystem is left out while the workspace does not exist: Dependabot resolves a manifest at the directory it is given, and with none it ends every scheduled run as a failed updater run, which is a red run on the default branch and a false positive for the flow that watches for one. It returns with the commit that creates the workspace, carrying the `build` prefix, and the propagation table binds the two. `/dependabot-pr` triages the `cargo` ones; a `github-actions` pull request bails at preconditions as out of scope for the first version.
